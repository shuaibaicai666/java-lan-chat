# Skill：Java 局域网聊天室系统开发规约

> 本文件是 AI 工程化实践中的**意图表达与需求分解**产物：把"要做一个局域网聊天室"这句话，
> 拆解为可验收的功能/性能/安全需求，并给出边界约束与验收标准。
> AI Agent 依据本规约生成代码，人工对高风险动作进行审批，最终以"测试与评测集"逐条验收。

---

## 1. 意图表达（一句话）

开发一个**纯 Java（JDK 21，无第三方依赖）**的局域网多人在线聊天室：
一台服务器 + 多个客户端，支持**登录、群聊、私聊、在线用户列表**，带 **Swing 图形界面**，
可在一台电脑（或同一局域网多台电脑）上运行演示，并可通过自动化测试集验证。

## 2. 需求分解

### 2.1 功能需求（FR）

| 编号 | 需求 | 验收标准（可验证） |
|---|---|---|
| FR1 | 用户可登录服务器 | 输入昵称 + 服务器地址/端口后建立 TCP 连接；登录成功后客户端收到欢迎消息与当前在线用户列表；重名登录被服务器拒绝并给出明确提示 |
| FR2 | 群聊 | 任一客户端发送的普通消息，1 秒内被广播给**包括发送者在内的所有在线客户端**，显示格式为 `发送者: 内容` |
| FR3 | 私聊 | 消息以 `@目标昵称 内容` 形式发送时，只有发送者与目标两人可见，第三方客户端收不到 |
| FR4 | 在线用户列表 | 任何客户端上线/下线后，**所有**在线客户端的用户列表在 1 秒内同步刷新 |
| FR5 | 正常退出 | 客户端点"退出"或关闭窗口后，服务器回收资源并向其他客户端广播下线通知与最新列表 |
| FR6 | 异常掉线检测 | 客户端进程被强制结束或断网时，服务器在心跳超时（默认 30 秒）内自动踢除该用户并广播最新列表 |
| FR7 | 服务器控制台 | 服务器提供图形控制台，实时显示监听端口、客户端上下线、异常等日志 |
| FR8 | 命令行客户端 | 提供 `--cli` 命令行模式客户端（无界面），用于自动化测试与远程演示 |

### 2.2 性能需求（PR）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| PR1 | 并发支持 | 服务器至少稳定支持 **30 个客户端同时在线**，全部能正常收发消息 |
| PR2 | 响应延迟 | 本机环境下消息从发送到接收的延迟 < 1 秒 |
| PR3 | 资源控制 | 服务器为每客户端连接使用独立处理线程，上限 100 连接；断开后线程及时回收，无泄漏 |

### 2.3 安全与健壮性需求（SR）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| SR1 | 输入校验 | 昵称：去首尾空格后长度 1~16，禁止包含协议分隔符 `\|`、`@`、`,`；违规输入被拒绝且服务器不崩溃 |
| SR2 | 协议鲁棒性 | 客户端发送畸形协议消息（如缺少参数的私聊指令）时，服务器返回错误提示且保持运行，不影响其他客户端 |
| SR3 | 线程安全 | 在线用户集合的并发访问必须线程安全；同一时刻多人上下线+群聊不产生脏数据或 `ConcurrentModificationException` |
| SR4 | 路径与资源 | 服务器退出时正确关闭 ServerSocket，释放端口；客户端关闭时停止心跳线程与读线程 |

## 3. 边界与约束

- **技术栈**：Java 21（LTS），仅使用 JDK 标准库（java.net / java.io / javax.swing / java.util.concurrent），无 Maven/Gradle 依赖，`javac` 可直接编译。
- **平台**：Windows（开发与演示），纯标准库代码可跨平台运行。
- **网络**：TCP + 自定义**行文本应用层协议**（UTF-8，每行一条消息，`|` 分隔字段），端口默认 **8888**。
- **客户端上限**：100；**心跳**：客户端每 10 秒发送 PING，服务器 30 秒无任何消息判定掉线。
- **不做的部分（明确排除）**：不做注册/密码、不做消息持久化/历史记录、不做文件传输、不做加密——保持"简单但完整"，防止范围蔓延。

## 4. 应用层协议规格（可验收的"接口契约"）

所有消息为一行 UTF-8 文本，字段以 `|` 分隔，回车换行结束。

| 方向 | 格式 | 含义 |
|---|---|---|
| C→S | `LOGIN|<昵称>` | 登录 |
| C→S | `CHAT|<内容>` | 群聊消息 |
| C→S | `PRIVATE|<目标>|<内容>` | 私聊消息 |
| C→S | `PING` | 心跳 |
| C→S | `LOGOUT` | 主动退出 |
| S→C | `WELCOME|<你的昵称>` | 登录成功 |
| S→C | `USERLIST|<u1,u2,...>` | 全量在线用户列表（逗号分隔） |
| S→C | `CHAT|<发送者>|<内容>` | 群聊广播（含发送者） |
| S→C | `PRIVATE|<发送者>|<内容>` | 私聊投递 |
| S→C | `SYSTEM|<文本>` | 系统通知（上下线、踢除等） |
| S→C | `PONG` | 心跳应答 |
| S→C | `ERROR|<文本>` | 错误（登录失败、非法指令等），随后服务器可主动断开 |

约束：`<内容>` 允许包含 `|`（按 3 段切分，取前两段为控制字段，剩余全部拼接为内容）；昵称禁止 `|`、`,`、`@` 与空白。

## 5. 高风险动作与人工审批点

以下为**需要人工审批、不允许 AI 自动决定**的高风险动作，Agent 生成代码后由人逐项检查：

1. **端口绑定与监听**：端口冲突时给出清晰错误并退出，不允许静默换端口。
2. **广播与踢人的线程安全**：用户集合必须使用并发容器或加锁，迭代广播时不允许边遍历边删除。
3. **异常掉线后的资源释放**：读线程异常/EOF/心跳超时后，必须从在线集合移除、关闭 Socket、不再向该客户端写数据。
4. **畸形输入**：任何解析失败都走 ERROR 分支，绝不允许抛未捕获异常导致服务器线程死亡。
5. **GUI 线程规则**：Swing 组件只允许在 EDT（事件分发线程）更新；网络读线程收到的消息必须 `SwingUtilities.invokeLater` 转投。
6. **心跳与退出**：客户端关闭窗口时必须先发 LOGOUT 并停止心跳定时器，避免残留线程导致进程无法退出。

## 6. 验收与评测方式

- **自动化**：`chat.test.TestRunner` 启动内置服务器 + 多个客户端连接器，执行 `docs/test-cases.md` 中的全部用例并输出 PASS/FAIL。
- **人工演示**：服务器 GUI + 3 个客户端 GUI 的群聊/私聊/上下线演示（录屏）。
- **性能验证**：30 并发客户端连接 + 广播延迟实测，数据写入报告"系统验证"章节。
